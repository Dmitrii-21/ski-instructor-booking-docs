# Хранимые сущности

Система предназначена для управления расписанием инструкторов горнолыжного курорта, услугами и онлайн-записью клиентов на занятия.

Для работы системы необходимо хранить данные о клиентах, инструкторах, услугах, расписании, записях, оплатах, уведомлениях и аналитических событиях.

## Основные сущности

| Сущность | Основные атрибуты | Кто взаимодействует | Характер данных |
|---|---|---|---|
| Клиент | id, ФИО, телефон, статус профиля, дата создания, история записей | Клиент, администратор, система онлайн-записи | Транзакционные данные |
| Инструктор | id, ФИО, специализация, уровень допуска, статус активности, контактные данные, рейтинг | Инструктор, администратор, клиент при выборе занятия | Транзакционные и аналитические данные |
| Услуга / тип занятия | id, название, тип занятия, длительность, цена, максимальное количество участников, уровень катания | Администратор, клиент, система записи | Справочные и транзакционные данные |
| Слот расписания | id, instructorId, serviceId, дата и время начала, дата и время окончания, статус слота, вместимость | Клиент, инструктор, администратор, система записи | Транзакционные данные |
| Запись на занятие / бронирование | id, clientId, instructorId, slotId, serviceId, статус записи, количество участников, дата создания, причина отмены | Клиент, инструктор, администратор | Транзакционные данные |
| Оплата | id, bookingId, сумма, статус оплаты, способ оплаты, идентификатор платежа во внешней системе, дата оплаты | Клиент, платежный сервис, администратор | Транзакционные данные |
| Уведомление | id, recipientId, тип получателя, канал, текст или шаблон, статус отправки, дата отправки, bookingId | Сервис уведомлений, клиент, инструктор | Транзакционные и логовые данные |
| Отзыв / оценка занятия | id, bookingId, clientId, instructorId, оценка, комментарий, дата создания | Клиент, инструктор, администратор | Транзакционные и аналитические данные |
| Файлы и медиа | id, ownerId, тип файла, ссылка на объект, размер, дата загрузки | Администратор, инструктор, клиент | Неструктурированные данные |
| Аналитические события | eventId, userId, eventType, timestamp, source, metadata | Система, аналитик, администратор | Аналитические данные |

## Акторы, работающие с данными

| Актор | Как взаимодействует с данными |
|---|---|
| Клиент | Просматривает услуги, инструкторов, свободные слоты, создает запись, оплачивает занятие, оставляет отзыв |
| Инструктор | Просматривает своё расписание, видит новые записи, получает уведомления |
| Администратор | Управляет услугами, инструкторами, расписанием, отменами и изменениями записей |
| Сервис онлайн-записи | Проверяет доступность слота, создает бронирование, меняет статус записи |
| Платежный сервис | Обрабатывает оплату и возвращает статус платежа |
| Сервис уведомлений | Отправляет SMS, push или email клиенту и инструктору |
| Аналитик / менеджер курорта | Анализирует загрузку инструкторов, популярность услуг, отмены и выручку |

## Ключевые группы данных

### Операционные данные

К операционным данным относятся клиенты, инструкторы, услуги, слоты расписания и записи на занятия. Эти данные напрямую участвуют в основном пользовательском сценарии онлайн-записи.

### Транзакционные данные

К транзакционным данным относятся бронирования, оплаты и изменения статусов. Для них важна целостность: запись не должна создаваться без проверки доступности слота, а один слот не должен быть занят двумя клиентами одновременно.

### Справочные данные

К справочным данным относятся категории инструкторов, услуги, варианты длительности, уровни катания и допустимое количество участников. Эти данные меняются редко, но часто читаются frontend-приложением.

### Логовые и аналитические данные

К логовым и аналитическим данным относятся уведомления, ошибки отправки, пользовательские события и данные для отчетности. Они нужны для анализа работы системы, расследования инцидентов и построения управленческих отчетов.

### Неструктурированные данные

К неструктурированным данным относятся фотографии инструкторов, документы, сертификаты, вложения и архивы отчетов. Такие данные нецелесообразно хранить напрямую в реляционной базе данных.
