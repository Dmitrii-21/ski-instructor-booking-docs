# Выбор технологии хранения

Для системы онлайн-записи необходимо выбрать несколько технологий хранения, потому что разные типы данных имеют разные требования к структуре, скорости доступа, консистентности и объему.

## Итоговое решение по технологиям

### Реляционная БД — основное хранилище

Для основных сущностей системы лучше использовать **реляционную базу данных**.

В неё стоит хранить:

- клиентов;
- инструкторов;
- услуги;
- расписание;
- слоты;
- записи на занятия;
- оплаты;
- отзывы;
- статусы бронирований.

Причина выбора: эти данные хорошо структурированы, имеют много связей между собой и требуют транзакционной целостности.

Например, при создании записи на занятие система должна одновременно:

1. проверить, что слот свободен;
2. создать запись клиента;
3. изменить статус слота;
4. при необходимости создать оплату;
5. зафиксировать результат.

Эти действия должны выполняться атомарно: либо вся запись создаётся успешно, либо система откатывает изменения.

Поэтому для ядра системы подходит **реляционная СУБД**.

Примеры подходящих технологий:

- PostgreSQL;
- MySQL;
- Oracle;
- MS SQL Server.

В рамках проекта наиболее подходящим вариантом является **PostgreSQL**, так как она поддерживает транзакции, ограничения целостности, индексы, enum-типы и хорошо подходит для связанных бизнес-данных.

### Key-Value хранилище — для временного удержания слота

Для временного удержания слота можно использовать **key-value хранилище**.

Например, когда клиент выбрал слот, но ещё не завершил оформление записи, система может создать временный hold:
