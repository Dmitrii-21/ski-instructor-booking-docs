# Диаграмма вариантов использования

Ниже представлена Use Case диаграмма процесса создания записи на занятие.

```plantuml
@startuml
left to right direction

title Use case диаграмма: создание записи на занятие

actor "Клиент" as c
actor "Администратор" as a
actor "Главный администратор" as ha

ha --|> a

rectangle "Запись на занятие" {
  usecase "Записаться онлайн" as uc1
  usecase "Записать клиента вручную" as uc2
  usecase "Ввести параметры\nзанятия" as uc3
  usecase "Выбрать слот" as uc4
  usecase "Заполнить личные\nданные" as uc5
  usecase "Проверить\nдоступность слота" as uc6
  usecase "Проверить\nспециализацию" as uc7
  usecase "Проверить длительность\nзанятия" as uc8
  usecase "Запись по\nтелефону" as uc9
  usecase "Запись через\nмессенджер" as uc10
  usecase "Запись у стойки\nадминистратора" as uc11
}

c --> uc1
a --> uc2

uc1 ..> uc3 : <<include>>
uc1 ..> uc4 : <<include>>
uc1 ..> uc5 : <<include>>

uc2 ..> uc6 : <<include>>
uc2 ..> uc7 : <<include>>
uc2 ..> uc8 : <<include>>

uc9 ..> uc2 : <<extend>>
uc10 ..> uc2 : <<extend>>
uc11 ..> uc2 : <<extend>>
@enduml
```

## Краткое описание

Диаграмма показывает два основных способа создания записи на занятие:

- онлайн-запись клиентом;
- ручную запись администратором.

Также на диаграмме отражены:

- основные участники процесса;
- включаемые действия при создании записи;
- варианты расширения ручной записи через разные каналы обращения клиента.
