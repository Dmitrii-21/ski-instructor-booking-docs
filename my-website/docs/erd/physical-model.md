# Физическая модель

Физическая модель уточняет логическую структуру данных под реализацию в PostgreSQL.

## Особенности реализации

Для полей выбраны конкретные типы данных:

| Тип данных | Где используется |
|---|---|
| `BIGSERIAL` | Идентификаторы сущностей |
| `VARCHAR` | Строковые значения ограниченной длины |
| `TEXT` | Описания и причины ошибок |
| `TIMESTAMPTZ` | Даты и время с учетом часового пояса |
| `NUMERIC(10,2)` | Стоимость занятия и сумма оплаты |
| `BOOLEAN` | Признаки активности и подтверждения |
| `enum` | Фиксированные наборы статусов |

## Enum-типы

Фиксированные наборы значений вынесены в `enum`, чтобы ограничить допустимые статусы:

| Enum | Назначение |
|---|---|
| `skill_level_enum` | Уровень катания клиента |
| `slot_status_enum` | Статус слота расписания |
| `booking_status_enum` | Статус записи на занятие |
| `booking_source_enum` | Источник создания записи |
| `payment_status_enum` | Статус оплаты |
| `payment_method_enum` | Способ оплаты |
| `recipient_type_enum` | Тип получателя уведомления |
| `notification_channel_enum` | Канал уведомления |
| `notification_status_enum` | Статус отправки уведомления |

## Ограничения целостности

Для защиты данных добавлены ограничения:

- запрет дублей слотов одного инструктора на одно и то же время;
- запрет отрицательной цены занятия;
- запрет отрицательной суммы оплаты;
- проверка корректного интервала времени слота;
- уникальность телефона клиента;
- уникальность логина и email администратора;
- уникальность внешнего идентификатора оплаты.

## Индексы

Индексы добавлены на поля, которые часто используются в поиске и фильтрации:

| Индексируемые поля | Назначение |
|---|---|
| `client_id` | Быстрый поиск записей клиента |
| `instructor_id` | Быстрый просмотр расписания инструктора |
| `slot_id` | Проверка занятости слота |
| `booking.status` | Фильтрация записей по статусу |
| `payment.status` | Обработка оплат по статусу |
| `notification.status` | Контроль отправки уведомлений |

## Обоснование физической модели

В физической модели логическая структура данных уточнена под реализацию в PostgreSQL: для идентификаторов используются `BIGSERIAL`, для дат и времени — `TIMESTAMPTZ`, для стоимости и сумм оплат — `NUMERIC(10,2)`.

Фиксированные наборы значений вынесены в `enum`, чтобы ограничить допустимые статусы слотов, записей, оплат и уведомлений.

Для защиты целостности добавлены уникальные ограничения и проверки, например запрет дублей слотов одного инструктора на одно время, запрет отрицательной цены и некорректного интервала времени.

Индексы добавлены на поля, которые часто используются в поиске и фильтрации: клиент, инструктор, слот, статусы записей, оплат и уведомлений.

Это позволяет ускорить ключевые сценарии системы: поиск свободных слотов, просмотр расписания, обработку броней, оплат и уведомлений.
