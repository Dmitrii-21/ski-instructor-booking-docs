# Концептуальная модель

Концептуальная модель отражает основные бизнес-сущности системы онлайн-записи клиентов на занятия с инструкторами горнолыжного курорта и связи между ними.

## Основные сущности

| Сущность | Назначение |
|---|---|
| Клиент | Пользователь, который оформляет запись на занятие |
| Инструктор | Сотрудник курорта, который проводит занятия |
| Категория инструктора | Специализация инструктора, например лыжи или сноуборд |
| Услуга | Тип услуги, доступной для записи |
| Вариант занятия | Конкретный вариант услуги с длительностью, ценой, количеством участников и уровнем катания |
| Слот расписания | Временной интервал, доступный или недоступный для записи |
| Запись на занятие | Центральная сущность, фиксирующая выбранное занятие клиента |
| Оплата | Информация об оплате занятия |
| Уведомление | Сообщение клиенту или инструктору о статусе записи |

## Ключевая логика модели

Центральная сущность — **«Запись на занятие»**, потому что она связывает клиента, инструктора, администратора, выбранный вариант занятия, слот расписания, оплату и уведомления.

**Услуга** отделена от **варианта занятия**, чтобы не дублировать параметры длительности, количества участников и стоимости для каждого типа услуги.

**Категория инструктора** связана именно с инструктором, так как отражает его специализацию.

Доступность инструктора вынесена в отдельные сущности: смену, блокировку времени и слот расписания. Это позволяет корректно отражать рабочее время по дням, недоступные интервалы и конкретные слоты для записи.

**Оплата** и **уведомления** выделены отдельно, потому что имеют собственные статусы и жизненный цикл.

## Основное бизнес-правило

Один слот расписания не может быть занят несколькими активными записями одновременно.
