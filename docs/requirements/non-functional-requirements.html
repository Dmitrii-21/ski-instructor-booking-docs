Нефункциональные требования

Security — безопасность​

IDТребованиеПриоритетОбоснование
NFR-SEC-001Все соединения клиентских интерфейсов с сервером должны выполняться только по HTTPS с использованием TLS 1.3MustПередаются персональные данные клиента: ФИО и телефон. Без шифрования есть риск перехвата и утечки данных
NFR-SEC-002Система должна разграничивать права доступа по ролям: клиент, инструктор, администраторMustКлиент должен видеть только свои записи, инструктор — только свои смены и записи, администратор — данные смены и справочники

Performance — производительность​

IDТребованиеПриоритетОбоснование
NFR-PERF-001Операции поиска слотов, поиска инструкторов и создания записи должны выполняться с временем ответа API не более 800 мс по p95 при нагрузке до 50 RPSShouldДолгая запись снижает конверсию и увеличивает количество незавершенных попыток записи

Reliability — надежность и доступность​

IDТребованиеПриоритетОбоснование
NFR-REL-001Доступность веб-сервиса и АРМ администратора должна быть не ниже 99.5% в месяц в сезонShouldСбой в пиковый день приводит к потере выручки и усложняет работу администраторов

Capacity — емкость​

IDТребованиеПриоритетОбоснование
NFR-CAP-001Система должна поддерживать хранение минимум 10 000 клиентов за сезон и 100 000 записей за сезон без деградации ключевых операцийShouldСистема должна выдерживать сезонную нагрузку без ухудшения поиска слотов и создания записей

Observability — наблюдаемость​

IDТребованиеПриоритетОбоснование
NFR-OBS-001Система должна логировать события создания, подтверждения, отмены и переноса записи, изменения смен и блокировок, а также ошибки отправки уведомленийShouldЛоги нужны для разбора инцидентов, восстановления истории действий и подготовки отчетов
NFR-OBS-002Логи событий должны храниться не менее 90 днейShouldТакой срок позволяет разбирать спорные ситуации и технические инциденты после их возникновения

Usability — удобство использования​

IDТребованиеПриоритетОбоснование
NFR-UX-001Пользователь должен иметь возможность создать запись не более чем за 6 шагов от выбора категории до подтвержденияShouldЧем короче путь записи, тем выше вероятность, что клиент завершит сценарий
NFR-UX-002Форма ввода данных клиента должна содержать минимальный набор обязательных полей: ФИО, телефон, уровень катания и согласие с пользовательским соглашениемShouldМинимизация обязательных полей снижает количество незавершенных записей

Maintainability — поддерживаемость​

IDТребованиеПриоритетОбоснование
NFR-MNT-001API системы должно быть документировано в формате OpenAPI 3.0CouldДокументация API упрощает разработку, тестирование и дальнейшее сопровождение системы
NFR-MNT-002Конфигурации окружений должны быть описаны так, чтобы новый релиз можно было развернуть по инструкцииCouldMVP быстро меняется, поэтому без описания окружений сопровождение будет сложнее

Compatibility — совместимость​

IDТребованиеПриоритетОбоснование
NFR-COMP-001Веб-интерфейс клиента должен корректно работать в последних двух версиях Chrome, Safari и FirefoxShouldКлиенты используют разные браузеры, поэтому базовая совместимость критична для доступности сервиса
NFR-COMP-002Веб-интерфейс клиента должен быть адаптивным для экранов шириной от 360pxShouldКлиенты часто записываются с телефона, поэтому интерфейс должен быть удобен на мобильных устройствах

Scalability — масштабируемость​

IDТребованиеПриоритетОбоснование
NFR-SCAL-001Архитектура должна позволять увеличить пропускную способность минимум в 3 раза без изменения бизнес-логики приложенияCouldВ праздники и высокий сезон возможны пики нагрузки, поэтому система должна иметь запас для роста

Legal / Compliance — нормативно-правовые требования​

IDТребованиеПриоритетОбоснование
NFR-LGL-001Создание записи должно быть возможно только после фиксации согласия клиента с пользовательским соглашением и обработкой персональных данныхMustСистема обрабатывает ФИО и телефон клиента, поэтому требуется юридически корректное согласие
NFR-LGL-002Система должна хранить факт согласия клиента: дату, время и версию соглашенияMustЭто снижает юридические риски и позволяет подтвердить факт согласия при спорных ситуациях
